## Najpierw dobre pytanie

Otwierasz edytor. Masz pomysł, kawę i narzędzie, które potrafi napisać prawie wszystko. Pokusa jest prosta: od razu poprosić o kod. Ale co właściwie chcesz zbudować? I dla kogo?

## Szybciej nie zawsze znaczy bliżej

Łatwo pomylić tempo pracy z postępem. Można w godzinę napisać mnóstwo kodu i ani o krok nie przybliżyć się do rozwiązania prawdziwego problemu. Warto zatrzymać się i nazwać to, czego jeszcze nie wiemy.

> Najlepsza linijka kodu? Czasem ta, której nie trzeba było napisać.

## Prototyp jako pytanie

Dobry prototyp nie musi przypominać gotowego produktu. Ma odpowiedzieć na jedno pytanie. Czy ten układ jest zrozumiały? Czy ta interakcja daje poczucie kontroli? Czy w ogóle potrzebujemy tej funkcji?

<Callout title="MAŁY EKSPERYMENT">

Weź pomysł, nad którym teraz pracujesz. Opisz go bez używania nazw technologii. Co pozostaje?

</Callout>

```ts
type Experiment = {
  question: string;
  scope: "small";
  steps: string[];
  doneWhen: string;
};

const question = "Czy osoba, która trafia tu pierwszy raz, potrafi znaleźć artykuł i wrócić do listy bez dodatkowego wyjaśnienia?";
const experiment: Experiment = {
  question,
  scope: "small",
  steps: [
    "Pokaż osobie testującej listę artykułów.",
    "Poproś o otwarcie tekstu, który ją zaciekawi.",
    "Obserwuj, czy odnajduje podsumowanie i spis treści.",
    "Zapytaj, co było jasne, a co wymagało zastanowienia.",
  ],
  doneWhen: "Osoba samodzielnie otwiera artykuł i wraca do listy.",
};

function prepareSession(plan: Experiment) {
  return {
    question: plan.question,
    checklist: plan.steps.map((instruction, index) => ({
      number: index + 1,
      instruction,
      observed: false,
    })),
    success: plan.doneWhen,
  };
}

console.log(prepareSession(experiment));
```

## Mniej decyzji na zapas

Nie każda możliwość musi stać się wymaganiem. Gdy zaczynam nowy projekt, próbuję oddzielić to, co potrzebne dzisiaj, od tego, co być może przyda się kiedyś. To zostawia więcej miejsca na zmianę zdania.

## Człowiek zostaje w pętli

Narzędzie może podsunąć dziesięć rozwiązań. Wybór nadal należy do nas. Wymaga znajomości kontekstu, rozmowy z ludźmi i zgody na to, że pierwsza odpowiedź nie musi być najlepsza.
