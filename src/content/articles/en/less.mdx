## Start with a good question

You open your editor. You have an idea, a coffee, and a tool that can write almost anything. The temptation is simple: ask for code right away. But what are you actually trying to build? And who is it for?

## Faster does not always mean closer

It is easy to confuse speed with progress. You can write a lot of code in an hour without getting any closer to solving the real problem. It helps to pause and name the things you do not yet know.

> The best line of code? Sometimes it is the one you never needed to write.

## A prototype is a question

A good prototype does not have to resemble a finished product. It needs to answer one question. Is this layout understandable? Does this interaction give a sense of control? Do we even need this feature?

Take an idea you are currently working on. Describe it without naming any technologies. What remains?

</Callout>

```ts
type Experiment = {
  question: string;
  scope: "small";
  steps: string[];
  doneWhen: string;
};

const question = "Can a first-time visitor find an article and return to the list without any additional explanation?";
const experiment: Experiment = {
  question,
  scope: "small",
  steps: [
    "Show the article list to a participant.",
    "Ask them to open an article they find interesting.",
    "Observe whether they find the summary and table of contents.",
    "Ask what felt clear and what required extra thought.",
  ],
  doneWhen: "The participant opens an article and returns to the list unaided.",
};

function prepareSession(plan: Experiment) {
  return {
    question: plan.question,
    checklist: plan.steps.map((instruction, index) => ({
      number: index + 1,
      instruction,
      observed: false,
    })),
    success: plan.doneWhen,
  };
}

console.log(prepareSession(experiment));
```

## Fewer decisions in advance

Not every possibility needs to become a requirement. When starting a new project, I try to separate what is needed today from what might be useful someday. This leaves more room to change my mind.

## Keep a person in the loop

A tool can suggest ten solutions. The choice is still ours. It requires context, conversations with people, and accepting that the first answer may not be the best one.

## What can you try tomorrow?

Before asking for another feature, write down the question it should answer in a single sentence. Build the smallest thing that helps you test it. Show it to someone. Then decide what comes next.
